# 连续图解式写作

## Purpose

把复杂技术内容写成可连续阅读的讲解：每一幕推进一个观点，用图解释关系，再用正文留下案例、边界和证据。默认采用自然纵向滚动；读者能选择文字、搜索、复制代码、跳转章节。

## 从已有材料开始

- 先读原文、站点约定、文章布局和主题；在现有 Markdown / Jekyll / 其他发布链路上工作。已有设计获准时直接执行，不重新收集同一偏好。
- 区分新写、改写和排版：改写默认保留信息、代码、引用与重要锚点；需要删减实质内容时说明取舍。排版不改事实。
- 材料里的假设案例继续标作假设；不把它写成作者的亲历，不编造数据、产品行为或来源。不把建议中的系统写成已经上线。
- 将读者最终应理解的结论写成一句话，再挑一个能贯穿全文的具体问题或对象。

## 写作配方

先用真实困境引出问题，再按理解依赖安排章节。常见顺序是「问题 → 原因 → 方法 → 案例 → 边界/反馈」，按题材调整，不机械固定幕数。

每一幕由以下部分组成：

1. **观点标题**：读者只扫标题也能复述主线；例如「这次修好了，还要证明下次能用」。
2. **关键图解**：选择流程、分层、对比或状态变化中最贴合关系的一种。简单段落可不配图；图必须补充理解，不能只是把正文句子塞进卡片。
3. **必要正文**：先交代结论为什么成立，再接同一个案例。段落短但保留技术细节，代码与条件不受视觉字数目标限制。
4. **按需展开**：只把补充证据、完整推导或大图放进原生 `details` 等披露组件；结论、限制条件、关键代码和必要警示保持直接可见。

整篇采用有节奏的留白与分隔，电脑可图文并排，手机改为纵向；不强制固定屏高，不拦截滚轮、空格、方向键或触摸滚动。沿用目录、评论、深浅色和阅读进度等现有能力。

需要措辞和信息保留示例时，读 [references/writing-example.md](references/writing-example.md)。

## 图解的颜色和运动

- 用色表达职责：例如蓝色代表输入/证据，橙色代表待验证/审批，绿色代表已验证能力，紫色代表跨域或归档。每张图根据自己的含义确定映射，跨章节同义保持一致；节点同时写清状态，不能只凭颜色区分。
- 视觉上可用浅底工程网格、细连接线、多色柔和填充和清楚的文字。复用本站主题变量；深色单独检查对比度。参考站用于提炼视觉语言，不直接搬运内容、品牌或完整代码。
- 动画回答「往哪走」「当前讲哪一步」「反馈回哪里」。优先连接线流动或当前节点依次强调，一张图最多突出一至两种运动。完整文字和关系在初始静态状态就可见。
- 连续循环只是过程示意，不能暗示真实业务已成功执行。分支、可选阶段和回路需标明条件；跨项目推广不是所有经验的必经阶段。
- 图解进入视野才运行，离开视野或页面隐藏即暂停；持续自动动画提供可访问的暂停/播放控制；遵守 `prefers-reduced-motion`，无 JS 时仍完整可读。打印展示静态关系。

实现动态图解或适配现有博客时，读 [references/visual-and-motion.md](references/visual-and-motion.md)；只有写作需求时不必加载实现细节。默认使用现有能力和轻量 CSS / 原生 JS，确有需要才引入库。

## 交付检查

- 对照原材料检查事实、限定条件、假设、代码和引用；能指出每张图在解释什么。
- 检查章节主线是否连续、读者能否扫标题理解结论；展开内容不是补救被藏掉的关键信息。
- 有页面实现时运行项目构建，实际查看桌面与 320–375px 手机、深浅色、暂停/播放、减少动态和禁用 JS。纯 Markdown 交付核对结构与关系，不声称验证过浏览器。
- 只对选择的文章启用新样式，防止普通文章回归；已有文章锚点保持稳定。
- 按已授权范围交付；写文章不自动授权推送、部署、修改全局规则或保存记忆。用户已经授权的发布/安装步骤无需重复询问。
