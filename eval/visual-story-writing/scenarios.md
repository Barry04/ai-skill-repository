# 连续图解式写作行为验收

本文件是仓库内行为样本，不随 Skill 安装；目前不声称有 CI 自动行为评分。

## A. 技术文章改写

输入：现有 Jekyll Markdown 文章含代码、引用、章节锚点。用户要求 PPT 式连续图解，颜色更丰富，有流线动画。

验收：沿用 Jekyll；保留实质内容与锚点；观点、图解和文字形成主线；按篇加载；手机纵向，深浅色可读；支持暂停、离屏/后台停止、减少动态与无 JS 静态阅读。无发布授权时不推送。

## B. 假设案例的口吻

输入：一份假设的登录排查记录变成多份近义笔记，经验证与批准入库，升级后复核退出。

验收：不改成作者「我曾经遇到」的亲历；三幕均跟随这份记录；批准与边界直接可见；不捏造收益；不把通用化设成必经阶段。

## C. 一段简单说明

输入：用户只想把一小段概念讲清楚，不需要网页或动效。

验收：给适量文字与必要小图，不强行分成五幕，不创建整套站点或引入前端依赖。

## D. 仅改排版

输入：用户要求保留全文，只改为图解式排版；原文有失败条件、长代码与参考来源。

验收：保留限制与代码，细节可以展开但核心条件不隐藏；不新增未核实事实，不把建议写成已实现能力。

## E. 页面不支持脚本

输入：用户博客只能发布 Markdown 或静态 HTML，不允许 JavaScript。

验收：静态图解完整可读；接受实际限制，不迁移站点，不承诺动态效果已经验证。

## 本次观察

基线代理在没有 Skill 时能够生成三幕结构、语义用色和减少动态方案，但将输入中的假设改成了第一人称亲历；未明确离屏、后台停止和持续动画的暂停控制。Skill 据此补充来源口吻与完整动效运行条件。独立试用结果以真实执行为准。

独立试用在加载 Skill 后保持假设口吻，使用同一案例，保留验证、批准、复核与替代方法，并提出手机重排、暂停和减少动态方案。页面独立审阅另发现闭合 details 的打印隐藏问题，已补充实现提示和实际浏览器打印验证；不据此宣称完整跨浏览器认证。
