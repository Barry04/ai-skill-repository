# change-lifecycle 验证记录

日期：2026-10-19。

## 新需求任务计划的独立对照

使用 5 个无指导样本和 5 个显式提供本 Skill 的样本。每个样本是独立上下文，没有共享先前答案或预期结论。

共同任务输入：订单后台增加分类功能，字段暂叫 `type`，页面可筛选；用户不想额外维护文档。项目没有需求单和发布信息，本轮可以完成实现和本地验证。要求给出具体改动计划、文件范围及结束说明，不实际写文件。

- 无指导的 5 份计划均未建立需求记录，均有“不新增独立文档”或同义表述。
- 其中 1 份将缺少发布信息表述为“尚未发布”；其余只报告本地完成。
- 有指导的 5 份计划均提出由 Agent 维护一份 `docs/changes/` 记录，将发布、调用方和数据保留信息标为未知，实现及本地验证完成后停在 `awaiting_self_test`。

这是任务计划层面的样本；没有测试宿主的隐式 Skill 匹配，也不能用它证明实际部署信息正确或所有模型都会遵循规则。

## 隔离临时项目的真实文件演练

准备：Python 订单序列化与筛选函数、3 个单元测试、一份原有待自测需求记录，以及一份无关手写笔记。原记录附有场景用户确认：只在自测环境、无独立调用方、自测数据无需保留。

任务：自测反馈将字段与筛选参数 `type` 统一改为 `category`，修复后还要继续自测。执行 Agent 只可修改该临时项目。

观察到的产物与独立复查：

- 实现和测试同步改名，3 个单元测试通过。
- 新字段序列化与筛选行为正确；仅传旧字段会失败，没有留下旧字段 fallback。
- 继续更新原来的唯一需求记录，保留相同需求 ID 和发布/依赖事实；阶段经过 `self_test_fix` 回到 `awaiting_self_test`，记录兼容决定与验证结果。
- 无关手写笔记字节未变，包括 Windows 文本模式产生的 CRLF。首次复查脚本误以 LF 比较，核实夹具原始创建方式后更正预期，重新检查通过；无需修改笔记或 Skill。

演练产物保存在隔离临时目录，不安装到真实业务项目，也不提交临时代码或日志。
