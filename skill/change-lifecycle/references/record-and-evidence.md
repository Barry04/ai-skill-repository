# 状态与证据约定

## 最小记录与归属

- 优先使用项目已有的需求单、变更文档及其编号，不同时维护内容相同的第二份记录。
- 缺少记录时，从用户请求提取目标，以代码探索补充范围；未确定的设计写成待定。可直接采用模板，不要求用户事后补一篇需求文档。
- 无约定时保存到当前项目 `docs/changes/YYYY-MM-DD-<slug>.md`；日期按用户所在时区，编号和文件名一经关联尽量稳定。
- 记录只含必要的需求结论、范围和证据摘要/引用，不保存聊天全文、敏感业务数据、凭据或原始生产日志。
- 手写代码接入时，以相关文件和已有差异建立范围；没有 Git 也可以使用可读的文件清单。不要重置工作区来获得“干净起点”。
- 范围重叠、同分支多需求或只有弱关键词时，不能自动合并记录。先问一个可消歧的问题。

## 两类状态

开发阶段建议使用：

```text
designing → implementing → awaiting_self_test
                                ↕
                           self_test_fix
```

用户或实际测试结果确认自测通过后可进入 `ready_for_release`。本地测试通过只说明本地验证；缺少人工自测或目标环境结果时继续等待。业务验收结束可以标记 `completed`，但这个阶段名称本身不改变任何发布或依赖事实。

`production_exposure.status` 的取值：

- `unknown`：没有足够依据，或者证据冲突尚未解决。
- `none`：已有明确依据说明所讨论的需求/版本尚未进入生产，不能由“没有找到部署记录”推断。
- `partial`：部分生产流量、用户或节点已使用该版本。
- `full`：已确认目标生产范围完成部署/启用。

外部调用方使用 `unknown` / `none` / `present`，这里指本轮修改范围之外的调用方，包括同一组织的服务或客户端。数据保留使用 `unknown` / `disposable` / `required`。只有明确事实支持时才填 `none` 或 `disposable`；“没有生产流量”不证明联调方和自测数据都可丢弃。

`deployments` 保存环境与版本事实，不能用它替代调用方和数据约束。

## 证据怎样写

证据可来自用户明确说明、可访问的部署记录、运行中版本、契约约定或数据确认。记录来源与范围，不要求为了例行记录额外审批。

```yaml
production_exposure:
  status: none
  evidence:
    - fact: 本需求仅部署到自测环境，尚未进入生产
      source: 用户明确反馈
      revision_scope: 本需求当前版本
      observed_at: 用户反馈时间
external_consumers:
  status: none
  evidence:
    - fact: 当前新增字段没有独立客户端或联调方
      source: 用户确认与调用方检查摘要
      revision_scope: 当前字段契约
      observed_at: 检查时间
```

以上是写法示意，不能把示例内容复制成已确认事实。一个事实的来源不能自动证明另外两个事实。用户说“仅自测”，只更新对应环境/版本的发布情况。

新部署、调用方接入、数据写入会使旧结论过时。核实冲突，更新当前结论，保留影响判断的历史事件与版本引用。曾进入生产后回滚，不能直接覆盖成“从未发布”：旧客户端、数据和在途请求仍需检查。

## 兼容决定的最少信息

```yaml
compatibility_decisions:
  - subject: 本次调整的字段或行为
    action: 直接替换、迁移、同步修改或临时兼容
    consumers: 具体调用方或数据范围；未知则写未知
    evidence: 支持该判断的事实引用
    removal_condition: 可观察的移除条件；无兼容分支则不适用
```

对于尚未发布且无保留义务的本轮错误实现，同步修改生产定义、所有已知调用和测试，删除过时分支。这里的“生产定义”指正式实现文件，不代表该代码已经上线。

对于已有依赖，先确定需要协调或迁移的范围。临时兼容应能说明何时删除，不能泛称“以后稳定再删”。已执行的数据库迁移需另行评估；未得到授权，不清库、不重建共享环境。

## 只读与触发边界

纯概念问答、一次性文字修改和无关文档维护不需要创建开发需求记录。用户要求只讨论或禁止写文件时，在回复中保留草案即可。

普通代码实施授权包含与需求直接相关的最小记录维护，不包含修改全局 Agent 配置、安装入口规则、发布系统或删除数据。需要稳定接入时提供 `assets/agents-rule.md` 片段，只有获准修改的入口文件才合并。

本 Skill 跟踪需求状态，不替代领域排错、测试或迁移流程，也不将每一次需求自动升级成新的 Skill。
