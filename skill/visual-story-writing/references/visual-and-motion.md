# 图解与动效实现参考

## 视觉配方

采用内容驱动的工程图：浅底、轻网格、细线和柔和多色节点。节点的颜色携带职责/状态，正文和标题保持高对比度。每图三至五个主要节点只是常见起点，复杂系统应分解视图，不能为凑节点删关系。

可选色板，需映射为项目语义变量；深浅色分别检查实际对比：

| 角色 | 浅色描边 / 底色 | 深色描边 / 底色 |
| --- | --- | --- |
| 输入、证据 | `#247fa3` / `#e7f2f8` | `#69bedf` / `#1c333f` |
| 验证、审批 | `#ba7c28` / `#faf0df` | `#e2aa60` / `#3b3022` |
| 已验证能力 | `#258b76` / `#e6f3ed` | `#62cbb0` / `#1b352d` |
| 跨域、退出 | `#8869b2` / `#f1ecf8` | `#b59bdc` / `#2e273d` |

这是一组视觉角色示例，同一篇文章中若紫色已经代表归档，不同时又让它代表相反状态。可以减少用色，必要时为新角色扩展色板。

## 结构与适配

- 流程优先语义 HTML 列表 + CSS；确实需要空间关系或精确连接才用 SVG。
- 桌面横向节点改为手机纵向，连接线同时改向；文字保持正常可读字号，不将整张 960px 图缩成手机宽度。
- 节点尽量一项职责、一句条件；复杂图可提供概览与可展开详图，详图应有明确提示。
- 正文使用真实文本和代码，配图使用 `figure` / `figcaption`，复杂图加可访问描述。保留原有 h2 ID，避免改版破坏外部锚点。
- Jekyll 示例：front matter 设 `reading_style: story`；布局按篇加载样式和脚本；`<section class="story-scene" markdown="1">` 中保留正常 Markdown。类名和键可按项目已有约定调整。
- Kramdown 的 `markdown="1"` 容器内可能采用不同的标题自动 ID 规则；改写已有 GFM 文章时，从原构建取出 h2/h3 ID，在新标题上用 `{#原有ID}` 显式保留，并对比生成结果。

## 动效控制模型

一个图的运行条件为：

```text
可见 && 页面前台 && 用户未暂停 && 系统未要求减少动态
```

- 用 `IntersectionObserver` 维护图解可见性，`visibilitychange` 维护前后台，`matchMedia` 响应系统设置变化。
- 用 CSS `transform` 移动流点；高亮当前节点时整段内容保持可见。避免逐帧读布局或动画改变段落高度。
- 简单阶段序列可用单个低频定时器；没有可播放图解时清除定时器。暂停/播放保留当前位置，返回视野后继续。
- 暂停按钮用原生 `button`，文字说明当前操作，并通过 `aria-pressed` 表达状态；至少 44px 触摸目标。不要用 `aria-live` 反复播报每次循环。
- 默认静态完整可读，JS 只增强。缺少观察器时保留静态关系，避免退化成所有图持续运行。
- 减少动态时停止流点、节点位移及阶段自动切换；打印保留所有关键节点和关系。
- 打印时需验证闭合 `details` 的正文确实可见；仅设置其子元素 `display: block` 不一定能解除内部隐藏。支持的浏览器可在打印媒体中设置 `details::details-content { display: block; content-visibility: visible; }`；其他目标环境按实际支持选择展开策略。

## 验证范围

1. 项目实际构建生成的 HTML 中标题、图解、代码和引用正确，Markdown 未变成原样标签。
2. 桌面和 320–375px 手机节点不挤压，正文无意外横向溢出，深浅色文字清楚。
3. 可见时播放，滚出视野后暂停；切到后台后暂停；暂停按钮可以恢复；系统设置变化即时生效。
4. 禁用 JS 与减少动态时能读完所有关系，普通文章不加载新资源。
5. 整理代码时以原文代码块、链接和已有标题锚点为对照；不能仅凭截图断言内容完整。
